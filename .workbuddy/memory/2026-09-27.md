- 素材：`~/Desktop/Nicolas 电子书/project+素材/AI音效/chess_move.wav`

  1. **开头 173ms 是纯底噪**（-58dBFS 的低频隆隆声），真正的撞击只有 173→210ms 共 ~37ms。

  3. 撞击后 215→384ms 不是自然衰减，是 -57dBFS 的平底噪 → 需要门限去噪。
  4. 频谱特征：能量集中在 250~500Hz（闷响），高频少 → 与旧的"清脆啪"是两种性格，
     反倒和现在默认的「重锤/力劈」轨迹更搭。

- 接入：存为 `Resources/sounds/move_1.wav`；`SoundEngine.groups["move"] = ["move_1"]`（单变体）；
  旧的 4 个合成变体移到 `native/tools/archive/sounds_synth_move/` 并从 Resources 删除。

## 吃子裂痕重做成「石刻凹槽」
- 用户反馈："裂纹太假，能不能做成石刻的样子，不行就做成浅一点的阴影线条，尽量别像线条"。
- 诊断（放大 12× 看旧渲染）：旧实现是"三层描边"——宽暗带 + 深色主缝 + 偏移 0.006 格的亮边。三个致命处：
  ① 等宽 → 读起来就是笔迹；② 一根到底 → 真裂缝会钻进石面又钻出来；③ **偏移的亮边平行浮在缝外侧** → 像"贴上去的细树枝"，而不是凹进去的槽。
- 新实现（FX/CrackLayer.swift 全部重写 + CrackForge 几何微调）：
  - 4 类层共 7 次填充叠出坡口：接触阴影 3 圈 → 背光侧壁 → 槽底 2 层 → 受光唇口。
  - 逐顶点独立宽度（根部粗→尖端收细 + 抖动 + 中段掐细到 0.26 倍）。
  - 几何更"石"：每段 32% 概率拐硬弯，其余只有小抖动。
- **踩到的两个坑（都已验证并写进 MEMORY）**：
  1. 亮边的左右符号要按"压印/deboss"规律：受光的是**背对光源那一侧**的壁（光从左上来 → 亮边落在下边）。第一版写反了，亮边贴在暗壁上。
  2. 亮边宽度必须乘 `|cross(纹路方向, 光线)|^0.6`，否则顺着光走的纹路上会出现通体均匀的亮线 = 又变回"线条"。
- 验证手段：把其它层 alpha 归零分别导出"只有槽底""只有亮边"，与 clear 场景相减做红青叠加图判定相对位置（/tmp/composite.swift）。
- 性能：每层把所有纹路合成一条 CGPath 一次填充（nonzero 取并集，要求所有带状多边形逆时针）；骨架每帧每纹路只算一次。单帧绘制 A/B（400 次重绘取平均）：空盘 0.21ms、5 道 0.57ms、40 道 3.15ms（旧 = 0.20 / 0.52 / 2.72ms）。优化前是 5.21ms，靠"骨架复用 + 直接写路径"降到 3.15ms。
- 回归基线已按约定重拍（`/tmp/xqbase`），4 个场景全绿。

## 裂纹走势改成「从棋子中心向外辐射」
- 用户反馈："开裂方式不够真实，要类似以棋子中心往外裂开的裂纹走势"。
- 诊断（放大看旧渲染）：像一丛**枯枝**——长纹横七竖八地乱伸、彼此不搭，看不出"中心"。
  根因是 `grow` 用**方向累积**（每步在上一段方向上再偏一点），偏角一路攒下去，长纹全拐成弧线。
- 顺带查出一个**索引错位 bug**：旧版把分叉细纹和主纹塞进同一数组，而分叉是**先** append 的，
  渲染层按"前 6 条 = 主纹"配粗细时拿到的全是短细纹 → **长主纹被画细、短分叉被画粗**，主次颠倒。
- 新实现：
  - `grow` 改成 `dir = a0 + dev`（a0 = 该纹的路由方向，dev 每步 ×0.82 收缩、夹 ±0.62 rad）。
    试过用"该点相对中心的方位角"驱动，结果分叉被拉回径向、与主纹连成一条直贯线，已放弃。
  - 主纹 3~6 条，角度**成簇**（间隔 0.35~1.75 倍均值，替代等分+抖动）；rank 洗牌决定长短与粗细
    （`wScale = 1.32−0.72·rank`，主次相差 2.6 倍）；伸展半径 0.40+0.30·power 格，累计长度到量即停。
  - 分叉概率 0.10+0.65·t（越靠外越多）、夹角 0.30~0.72 rad（夹角大就成"虫足"）、可到 depth 3、受 room 限制。
  - `CrackSink` 分桶 + `Crack.mainCount`/`weights`；`taper = 0.14+0.86·(1−t)^0.85`；生长期间末端 ×0.42 保持楔形。
  - 出场错开：主纹 hash 差 0~55ms、细纹再晚 55~90ms。
  - 中心砸痕改成 3 团偏心渐变叠出的不规则暗斑（单层 alpha 0.19）。
- 验证：单独编译 CrackForge + Rng 跑纯逻辑 dump（`/tmp/forgetest/ft`）确认主 3~6 条、伸展 0.4~0.9 格。
- 性能反而更快：单帧绘制（400 次重绘取平均）空盘 0.20ms / 5 道 0.45ms / 40 道 2.08ms（上一版 0.21/0.57/3.15）。
  40 道仅占 60fps 预算的 12.5%。
- 回归基线重拍后全绿。
- 对比图存到 `效果预览/裂纹走势对比.png` 与 `..._放大7x.png`。
- **踩坑（工具）**：Read 工具对**同一文件名**的图片会误报"内容未变"，即使文件已更新。
  确认构建链路是否真的生效，要用"临时把参数改成夸张值 → 编译 → 比 md5"这种决定性测试；
  读图则改用带时间戳的文件名。

## 吃子裂痕：按用户给的「碎裂石板」参考图做第四版（F~I，待用户挑选）
- 用户给了张碎裂石板照片问"可以参考图片裂纹吗"。从图里提取的可用读数只有两条：
  ① **块与块之间是宽而近黑的"沟"**（不是线）—— 图上暗部占全图 17%；
  ② 碎区**轮廓是碎块自己断出来的锯齿口**，不是一圈光滑界线。
- 预览台仍在 `/tmp/xqcrk`（`bash build.sh` 编译、`bash shoot.sh <style> <out.png> [n] [sq]` 出图、
  `XQ_CKSTYLE=6..9` 选新族、`gallery.swift` / `zoom.swift` 拼对比图；新族定义在
  `src/FX/CrackStylePreview.swift`，渲染在 `src/FX/CrackLayer.swift` 的 `drawShatter`）。
- **算法（关键，正式落地时照搬）**：`shatter()` ——
  1. 在冲击点周围撒 `pieces×3.8` 个种子（半径 1.95·rz 的圆内，r=R√u 才是面积均匀），做**功率图**
     （加权 Voronoi，权重幅度 spread 定块的大小差异）；
  2. **只取离冲击点最近的一撮碎块当"碎区"**，收块规则两条一起用：
     ① 硬约束：加到超过 80% 棋子面积立刻停（只判"够没够"会冲到 83%）；
     ② 逼近目标：离目标更远也停（只留硬约束会过分保守，实测掉到 46%）。
     目标面积取区间偏上（F 0.68 / G 0.76 / H 0.56 / I 0.64）。
  3. 裁切半平面先算好存起来，再按"邻居碎没碎"决定缩不缩半个缝宽 —— **与没碎的邻居之间那条边不缩**，
     于是碎区外缘没有环绕一圈的黑沟；
  4. 收完按**面积加权重心**把整片碎区拉回冲击点（否则会偏出去，"最近的一撮"不一定正对）。
- **三个反复踩到的坑**：
  1. 一开始"先画个圆再把碎块裁进去" → 碎区轮廓是圆弧 + 每块边缘一圈坡口 → 闭合成圆环，
     不管里面碎得多好，整片都读成"贴上去的圆标签"。**必须让碎块的边自己构成轮廓**。
  2. 碎块整体提亮 → 石板上留一块比周围亮的补丁，同样是"贴片"感。**亮度差只能发生在块与块之间**。
  3. 沿轮廓一圈均匀的亮唇 = 玻璃碎片。亮唇要按 `|法线·光线|^1.7` 只留给正对光的边且又窄又淡；
     断口的主体读数是"暗"。
- 缝 = **未缩块 − 内缩块**（nonzero 一次填充：未缩块正绕、内缩块反绕）。缝外再叠一层外扩 0.82 的
  接触阴影做"凹下去"。共享顶点用 `jittered()` 按**坐标**取随机数（索引取会裂开成两块），
  再 `chipEdges()` 把长直边打断成 2~3 段短直边（功率图的边是长直中垂线，不打断就是"切开的饼"）。
- 实测碎区面积比（硬约束 30%~80%，`area.txt` 输出，4 个格位各测一遍）：
  F 63~73%（3~4 块）/ G 67~78%（3~4 块）/ H 58~62%（6~9 块）/ I 51~68%（4~5 块）。
- 对比图存到 `效果预览/裂纹碎裂对比.png`、`..._放大8x.png`、`..._多格位.png`。
  **等用户在 F/G/H/I 里挑一个再落地正式源码**（正式 `Crack` 需要加 `cells / cellsFull / cellShade / seam` 四个字段，
  渲染入口在 `CrackLayer.drawShatter`）。
- 出图定位坑：预览 App 的棋盘是**镜像**的（x 轴翻），sq→屏幕坐标不能按 `c = sq%9` 直算；
  多格位出图时直接用"与 clean.png 差分取被改动像素的外接框中心"来定位，最稳。
