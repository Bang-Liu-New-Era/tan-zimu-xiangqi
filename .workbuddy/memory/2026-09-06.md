# 2026-09-06 开发记录

## 需求: 教学版原生 App (不依赖 HTML 打开)
用户要求: ①不要 HTML 双击执行, 改成封装成可执行的程序; ②增强教学能力; ③允许更多 UI 特效。

## 方案与成果
- 用 **Swift + WKWebView** 把象棋封装成原生 macOS `.app` (`native/XiangqiApp.swift`), 编译零下载(本机有 swiftc 6.3.3 + Xcode + AppKit/WebKit)。
- 新建 **教学模块 `engine/coach.js`**: hint(提示+理由)/ threats(威胁, 仅在对方能赚子时报)/ commentary(讲解: 开局名/将军/战术)/ tactics(双将/马后炮/重炮/捉双)/ evaluate(局势)/ assessMove(走子质量点评)。
  - 关键修正: threats 初版用 isAttacked 逐格且把"亏本换子"误报成威胁 → 改为基于 generateLegalMoves(opp) 过滤 capture 且 v>=av; 捉双初版误把"全盘有>=2可吃子"当捉双 → 改为 forkCount(同一子攻击>=2敌子)。已 node 验证。
- 教学界面 `native/Resources/`(index.html/style.css/app.js): 评估条/威胁列表/讲解/提示/点评面板; 特效: 吃子粒子+红环"吃"字、被将震屏红闪、提示发光、上一步箭头; 经 window.webkit.messageHandlers.xiangqi 向原生发音效事件。
- 原生侧: 工具栏(新对局/悔棋/认输/提示/先手/难度/教学开关)+ 菜单 + NSSound 播放打包 WAV(generate_sounds.py 生成 move/capture/check/win/lose/click)。
- 打包 `native/build_app.sh`: 复制 engine/*.js + Resources → swiftc 编译 → Info.plist → ad-hoc codesign + xattr -cr。产物 `native/build/人机中国象棋.app` (Mach-O arm64)。

## 验证
- node --check 全部 JS 通过。
- DOM 桩 test_native.js 真实加载四脚本并模拟点击走子/AI应招/提示/悔棋/认输, 无运行时崩溃。
- 启动二进制 4s 进程存活无报错日志。
