## 修复走棋规则引擎两处 bug（用户实战发现「马被士蹩腿却仍报将军」）
- 用户报告：黑方马被红士蹩腿，引擎仍报它能到红方三路将军。定位到 `engine/xiangqi.js` 的 `isAttacked()`（将军/攻击判定），
  **走子端 `genHorse()` 一直是对的**，所以用户走马会被拦，但 AI/将军提示错 —— 典型「两端不一致」症状。
- **bug ①（用户报的）**：`isAttacked` 马检测腿方向写反。[dr,dc] 是「目标→马」偏移，马吃目标的走子向量是 (-dr,-dc)，
  腿 = `ar - dr/2, ac - dc/2`，原代码写成 `+` → 检查了马背离目标那侧（常越界，Int8Array 越界读 undefined ≠ 0 被当蹩腿）。
  6 个方向假报攻击（假将军）、2 个方向漏报，双向都错。
- **bug ②（排查中发现）**：`isAttacked` 完全没有**象**的攻击检测（对拍暴露黑象吃格漏报）。已补：田字 + 象眼（`ar - dr/2` 同马腿逻辑）
  + `inElephantHalf(byColor, r)`（目标须在攻击方半场）。
- **误修警示**：中途给直线扫描加过 `if (pt === C) return true`（以为炮可贴脸吃）——**错**，象棋规则炮无炮架不能吃子，
  第一个子是炮时不 return（它接着当翻山炮架）才是对的。已撤销并写注释。
- **isAttacked 语义边界（重要，别再误判）**：target 上是攻击方自己的子、或空格时，isAttacked 会「多报」；
  但将军判定里 target 恒为对方王，这些差异不影响正确性。对拍时要排除空格与己方子占格。
- **验证链（全过）**：
  1. 单元：用户场景（马(7,3) 士(8,3) 蹩腿不将军）+ 8 方向蹩腿/无蹩对照 + 走子端交叉验证。
  2. 独立暴力实现对拍（自写 ~120 行，palace 还漏了上界 r≤9，修后）与引擎 depth3 内零分歧。
  3. **权威终审 xqwlight**（GitHub api 拉的 position.js，本机 github.com 被阻断但 api.github.com 通）：
     perft 44 / 1920 / **79666** 三层全同 + depth-2 divide（局面 FEN 指纹匹配，44 根着法）完全一致。
  4. **教训：我记忆里 perft(3)=79022 是错的**，白追了 644 的「差异」一轮半。跨引擎对拍才是硬基准。
